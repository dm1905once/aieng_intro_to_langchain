Theory

Now that you have a good grasp of the various components of LangChain, let's see how they all work together. To make this seamless, almost everything in LangChain is designed to be a runnable — llms, prompts, tools, retrievers, and others. Runnables provide a consistent interface for interacting with various components. This makes it easy to build and modify complex LangChain applications by chaining different components together into pipelines. They are designed to make LangChain more modular, composable, and easier to work with.

Runnables

Runnables are a fundamental concept that provides a standard interface for all components in a LangChain application. This interface defines a set of methods that allow you to interact with and execute that component in a consistent way. This is important for various reasons:

  • Because all runnables share the same interface, you can easily chain them together to create pipelines;

  • They abstract away the underlying implementation details of different components. Whether you are using an LLM, a prompt, a tool, or a retriever, you interact with them through the same .invoke method (and other runnable methods). This makes it easier to swap out components without rewriting large parts of your code;

  • They provide a unified way to execute different LangChain components;

  • You can define a runnable component once and then reuse it in different parts of your application or in different applications altogether.

Runnables typically implement the following methods (both synchronous and asynchronous versions are usually available):

  • invoke(input) / ainvoke(input) — this is the core method. It takes an input and executes the runnable logic, returning an output. This is how you "run" a runnable with a single input;

  • batch(inputs) / abatch(inputs) — executes the runnable on a list of inputs in batch. This is often more efficient for processing multiple inputs at once;

  • stream(input) / astream(input) — returns an asynchronous stream of output chunks. This is particularly useful for LLMs, where you want to get responses token by token and display them in real-time;

  • transform(input) / atransform(input) — similar to invoke but designed to be used within pipelines for step-by-step processing.

Think of runnables like Lego bricks. Each runnable is a brick with a standard way of connecting to other bricks (the runnable interface). You can take different types of Lego bricks (LLMs, prompts, tools) and easily snap them together to build more complex structures (LangChain applications and workflows).

Composing runnables (pipelines)

You compose runnables into pipelines using the | operator. This operator takes the output of the runnable on the left-hand side and feeds it as input to the runnable on the right-hand side. For example:

# Install packages: 
# pip install langchain-core langchain-groq

from langchain_core.prompts import ChatPromptTemplate
from langchain_groq import ChatGroq
import dotenv

dotenv.load_dotenv()

llm = ChatGroq(model="llama-3.3-70b-versatile")
prompt = ChatPromptTemplate.from_template("Tell me a joke about {topic}")

chain = prompt | llm  # Create a chain by composing prompt and LLM
# another way of creating a chain without using the | operator:
# chain = prompt.pipe(llm)

joke = chain.invoke({"topic": "cats"})
print(joke.content)

In this example, prompt is a runnable (a ChatPromptTemplate) and llm is also runnable (a ChatGroq model). You create a new runnable, chain, by combining the two. This chain represents the pipeline: first apply the prompt, then pass the output as input to the LLM. Data flows step-by-step:

  1. chain.invoke({"topic": "cats"}) is the initial input to the chain;

  2. prompt is invoked with {"topic": "cats"}. It outputs a PromptValue (the formatted prompt);

  3. The PromptValue output from prompt becomes the input to llm;

  4. llm processes the prompt and generates a chat messages containing the joke;

  5. The final output is the joke from the LLM.

You can read more about how runnables and the LangChain Expression Language work in the documentation.

Functions as runnables

Sometimes, you'd like a custom function to run as part of a chain. However, functions are not runnables. RunnableLambda allows you to convert a function (and other callables) into a runnable. This allows your function to support the standard interface provided by other runnables in LangChain. Let's see an example:

from langchain_core.runnables import RunnableLambda
from langchain_core.runnables import chain

def simple_function(text: str) -> str:
    return text.upper()

# Convert to a RunnableLambda
func_as_runnable = RunnableLambda(simple_function)

# another way is to use the @chain decorator
@chain
def another_simple_function(text: str) -> str:
    return text.capitalize()

# Invoke the runnable
result = func_as_runnable.invoke("hello langchain!")
print(result)
print(another_simple_function.invoke("HELLO WORLD!"))

Before converting the function to a runnable, it would not be possible to use methods such as .invoke and the others. After conversion, this is now supported. If your function is included as part of a chain, LangChain will automatically convert it to a runnable and you will not need to convert it into a runnable explicitly. Therefore, the following syntax is valid:

chain = prompt | llm | simple_function # simple_function will be treated as a runnable here

You can read more about this in the documentation.

Description

Congratulations on making it so far. At this point, your question-answering system can respond to user queries, utilize external data stores, and even use tools! Let's put it all together by composing a nice pipeline to tie up everything together. In this stage, you will further enhance your system and ensure everything is linked together.

Your system should use every component we have learned so far. When a prompt is issued, the first chain should be about properly formatting it with a prompt template to prepare it for the model. The output should be the input to the second chain — a model bound with tools. The output of this chain should be passed to a final chain which will execute the tools and print the output. Your system should therefore utilize three chains.

Objectives

Here are the objectives for the stage:

  • Take a user's query as input and format it with a prompt template;

  • The user's query is passed to the LLM with tools;

  • Create a custom function to implement the logic for running the tools;

  • Invoke the chain and pass the user's query as the initial input.

To ensure that the tests can verify your solution, include a print statement that will display information about your chain. It should be as follows: 

# other outputs
print(<chain_name>)
